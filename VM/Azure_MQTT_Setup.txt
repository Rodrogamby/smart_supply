1. CONFIGURATION FILE CONTENT

Paste into /etc/mosquitto/conf.d/spps.conf:

# MQTT over TLS
listener 8883
protocol mqtt

# Require authentication
allow_anonymous false
password_file /etc/mosquitto/passwd

# Server certificate and private key
certfile /etc/mosquitto/certs/fullchain.pem
keyfile /etc/mosquitto/certs/privkey.pem

Save: Ctrl+O, Enter. Exit: Ctrl+X.

Port 8883 is the conventional MQTT TLS port. The certificate and key
configuration actually enables TLS; choosing the port alone does not.

3. AUTOMATIC CERTIFICATE RENEWAL

Certbot renews the originals under /etc/letsencrypt/.
Mosquitto uses protected copies under /etc/mosquitto/certs/.
A deploy hook updates those copies and reloads the broker.

sudo nano /etc/letsencrypt/renewal-hooks/deploy/mosquitto.sh

Paste:

#!/bin/sh
set -eu

CERT_DIR="/etc/letsencrypt/live/retotest.mexicocentral.cloudapp.azure.com"

install -o root -g mosquitto -m 640 \
  "$CERT_DIR/fullchain.pem" \
  /etc/mosquitto/certs/fullchain.pem

install -o root -g mosquitto -m 640 \
  "$CERT_DIR/privkey.pem" \
  /etc/mosquitto/certs/privkey.pem

systemctl reload mosquitto

Save and exit. Then run:

sudo chmod 750 /etc/letsencrypt/renewal-hooks/deploy/mosquitto.sh
sudo systemctl enable --now certbot.timer
sudo certbot renew --dry-run --run-deploy-hooks

Verified result: all simulated renewals succeeded.

Keep HTTP port 80 reachable for the Nginx HTTP validation used by
this certificate configuration.

6. LOCAL MQTT TEST — TWO SSH SESSIONS

Problem observed:
The VM's MQTT clients stalled when connecting through the hostname
resolving to its own public IP. Direct local TLS worked.
The exact cause of that public-IP route failure was not established.

Temporary workaround, run ONCE inside the VM:

echo '127.0.0.1 retotest.mexicocentral.cloudapp.azure.com # spps-local-test' | sudo tee -a /etc/hosts

This affects the VM only. It retains hostname verification while
routing locally. Laptop and ESP32 DNS resolution are unaffected.

First SSH session — subscriber:
mosquitto_sub -h retotest.mexicocentral.cloudapp.azure.com -p 8883 --cafile /etc/ssl/certs/ca-certificates.crt -u reto -P 'reto' -t test2 -v -d

Second SSH session — publisher:
mosquitto_pub -h retotest.mexicocentral.cloudapp.azure.com -p 8883 --cafile /etc/ssl/certs/ca-certificates.crt -u reto -P 'reto' -t test2 -m "Hola de nuevo" -d

Verified subscriber output:
test2 Hola de nuevo

Diagnostic messages:
CONNACK (0): connection and authentication accepted.
SUBACK: subscription acknowledged.
PUBLISH: message received by subscriber.
PINGRESP: broker responded to the keepalive request.

The subscriber stays running. The publisher sends and exits.

-t test2 and -t "test2" are equivalent.
The shell removes the quotes. An actual newline inside quotes would
be part of the topic; a visual terminal line wrap is not.

To remove the temporary local override after testing:
sudo sed -i '/# spps-local-test$/d' /etc/hosts

Removal has not been confirmed. Removing it restores public DNS
resolution inside the VM and may reproduce the earlier route issue.

10. COMMAND AND PERMISSION REFERENCE

sudo       Run with administrator privileges.
apt update Refresh package lists; does not upgrade installed packages.
apt install -y
           Install packages and automatically confirm prompts.
systemctl enable --now
           Enable service at boot and start it immediately.
systemctl is-active
           Check current service state.
chown root:mosquitto
           Set owner root and group mosquitto.
chmod 640  Owner read/write; group read; others no access.
chmod 750  Owner full access; group read/traverse; others no access.
           For directories, execute permission means traversal.
-h         Broker host.
-p         Port (lowercase).
-u         MQTT username.
-P         MQTT password (uppercase).
-t         MQTT topic.
-m         Message payload (publisher).
-v         Display topic and payload (subscriber).
-d         Show MQTT diagnostic messages.
--cafile   Trusted public CA certificates used to verify the server.
-L         Complete connection URL; requires a URL argument.
           It is not a loopback flag.

Mosquitto runs as a background service even after SSH disconnects,
provided the VM remains running.

fullchain.pem: public server certificate and chain.
privkey.pem: secret server private key; do not share its contents.
isrgrootx1.pem: public CA trust certificate, not a private key.

A new hostname requires a certificate covering that hostname.
Changing only the IP does not require a new certificate if the same
hostname continues to resolve correctly.
